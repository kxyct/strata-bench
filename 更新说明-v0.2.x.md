==================== v0.2.1 ====================
**Update 0.2.1.1 (2026-10-20): Windows Terminal fix.** On Windows with long paths off (the default), the Terminal could not install an AMD engine: "The engine could not be installed. local file operation failed (FileNotFoundError)". The engine is now unpacked into a much shorter folder and with paths Windows accepts at any length, and a path that is still too long gets a plain message. If you use the Terminal on Windows, install it again once with `irm https://github.com/Niko1221/Strata/releases/latest/download/install.ps1 | iex` (your models and settings stay); it installs Terminal 0.1.46.1, and `strata launch` works again. (`strata update` downloads 0.1.46.1 too, but the Terminal on your PATH keeps starting the old version; that is fixed in the next release.) A new install gets it straight away. The app and the engines are unchanged.

**0.2.1: a task board in the app, pictures on the Mac and on Intel Arc cards, `strata bench run` with a fixed standard benchmark, faster downloads, Docker images, and your own engine settings are no longer overwritten.** It also fixes the crashes, stuck downloads and GPU-choice bugs reported on 0.2.0-beta. Each new default below says what it was measured on and whether the answers are identical to 0.2.0. ## What is new

- **A task board in the app.** On the Tasks screen, a Schedule | Board switch shows your scheduled tasks and loops as a board: what is running, what is waiting for your approval (from every chat), and what failed. Each run has one plain line, only the newest problem of a task is shown, and a problem can be dismissed. The sidebar shows how many tasks need you. All eight app languages are translated.
- **Pictures on the Mac.** The Mac app and Terminal now read pictures by default. The reader runs on the Mac's GPU (Metal), built into `strata-vision` and signed with the app. Measured on an M4 Mac: a 260-token picture 0.45 s on the GPU reader against 50.7 s on the CPU, a 972-token picture 2.4 s against 194 s; the GPU reader takes about 1.2 GB of memory. On the 972-token picture 8 of 972 picture tokens differ from the CPU reader (cosine down to 0.48, in the text area); the answers were correct. `--vision cpu` is still there and warns that it takes about 50 seconds per picture.
- **Pictures on Intel Arc cards.** Alchemist cards (A-series) read pictures by default through the CPU reader; Battlemage (B-series) stays opt-in (see Known limits). A new GPU picture reader for SYCL (`--vision gpu`) takes 0.16 s per picture on an A750 against 1.73 s on the CPU (its picture embeddings equal the CPU reader's to a cosine of 0.9959 to 0.9999). Ten varied pictures and a multi-picture chat all passed on the A750.
- **`strata bench run` runs the standard benchmark.** The default suite is `standard-v1`: fixed request files (34 of them, with a checksum list) in the Terminal archive, a scorer, a validator and a report that leaves out personal data. The Terminal archive now carries its commit, because a run without one does not count. The protocol text in `docs/BENCHMARK_PROTOCOL.md` is still a draft. See `docs/COMMUNITY_BENCHMARKS.md` for how to send a result.
- **Faster downloads.** Big model files come over 16 connections with several pieces per request (0.2.0 used 8 connections and a new connection for every piece). On the test PC, from Hugging Face, three interleaved pairs: 68.6 / 65.9 / 70.6 MB/s before, 74.4 / 74.8 / 74.9 MB/s now (+9%; the line itself tops out near 75 to 85 MB/s). The fetch of the draft layer (MTP) went from 25.0 / 28.1 / 37.6 MB/s to 47.4 / 50.5 / 52.2 MB/s, and its file list from 28 s to 4.6 s. ModelScope downloads, whose server reports no file length, now use several connections too. The files are the same and are still checked against their pinned SHA-256.
- **Docker images.** Ready-made images for `ghcr.io/niko1221/strata:0.2.1-<flavor>`: `cuda13`, `cuda12`, `rocm-gfx120x` (RX 9000, R9700), `rocm-gfx110x` (RX 7000) and `rocm-gfx1151` (Strix Halo). They are built from the signed release packages by the repository's workflow. The start-up test passed on an RTX A4000 (cuda13 and cuda12) and on a Radeon AI PRO R9700 (rocm-gfx120x); the gfx110x and gfx1151 images were built but not run on a card. There is no Intel image yet. See `docs/DOCKER.md`. The workflow starts after this release is published, because it reads the release's own files, so the images appear a few hours later.
- **Your own engine settings stay.** The app and setup used to rewrite the run config on every Load. Options you set by hand (`--vram-reserve-mib`, control vectors, any option setup does not choose itself) are now kept in `user_args`, and what you set wins over what the app generates. See Fixes.
- **Draft layer (MTP) switch.** Settings > Expert has a Draft layer (MTP) on/off per model, and `strata launch --mtp on|off` does the same. A picture-off choice and a custom context size stick across loads.
- **Fit checks count the draft layer.** With MTP on, the draft layer takes about 1 GB of graphics memory; the model fit check and the expert-cache sizing now count it.
- **The model page shows the engine's own pick for your PC** (the memory tiers of 0.2.0), with Gyro-M named as the other choice at 40 GB.
- **The chat footer speed is the writing speed.** It divides output tokens by decode time, so a tool-call turn no longer shows "632 tok/s" when the engine ran at 50 to 75.
- **A wrong download says so.** An installer for another make of graphics card (an AMD build on an NVIDIA PC) tells you in plain words which file to get and does not unpack its engine. An installed engine with no model loaded is no longer reported as "No Strata engine".
- **Terminal.** A model that is already on disk says "already downloaded". `strata monitor` finds a running `strata launch` without `--url`.
- **The standard AMD packages carry the hipBLASLt tuning tables** and the engine start picks the one for the card (see New defaults for when it is used).

## New defaults, with what we measured

Speed numbers are medians of interleaved pairs on the same box, a fresh engine per run; "pairs faster" counts the pairs the new default won. Each default has an off switch.

- **Mini PCs with a Radeon 780M (gfx1103), Linux: the matrix-core prompt set is on.** Measured on a Ryzen 7 8745HS with a Radeon 780M, 60 GB DDR5, Linux kernel 7.0.0-38, Qwen3.8-Flash-Next Q2_0 with MTP, 6 interleaved pairs: a 1K prompt 98.5 to 157.3 tok/s (x1.60, 6 of 6 pairs), a 4K prompt 115.1 to 233.3 (x2.03, 6 of 6), decode unchanged (x0.999 and x1.000). The greedy token ids equal the old default's in every pair (6 of 6, and 5 of 5 in the final build). Same answers, as far as the ids show. `STRATA_IGPU_PROMPT_SET=0` turns it off. It applies to the 780M and 760M on Linux only; 880M, 890M, Strix Halo and Windows stay off. The 780M's GPU can still reset on its own firmware (see Known limits); with the set on we saw no more resets than with it off, in small samples.
- **Strix Halo (gfx1151): the hipBLASLt tuning table is on.** The packaged Strix Halo engines (Linux `strixhalo` and the Windows `rdna3` package) use the table for their card when their hipBLASLt version matches it. The measurement is a community A/B from `bench/results/2026-10-05-community-gfx1151` (Linux, ROCm 7.17, hipBLASLt 1.5.0): prompts 250.9 to 528.9 tok/s (2.11x). We have no Strix Halo and did not repeat it. The table changes which matrix-product algorithm reads the prompt, so the answers are not bit-identical to plain hipBLAS (on an R9700 the first-token KL was 0.016, against a run-to-run difference of 0.00004; top-1 the same on 24 of 24 prompts). `STRATA_HIPBLASLT_TABLE=off` turns it off. On every other card the table is opt-in (`STRATA_HIPBLASLT_TABLE=on`): on the R9700 a table calibrated for the packaged hipBLASLt gave about +1% prompt and -2% decode, so none is shipped as a default. The tables are packaged per card (`tuning/` inside the engine package): Windows `rdna3` gfx1100 and gfx1151, Windows `hip` (RX 9000, R9700) gfx1201, Linux `rx7900` gfx1100, Linux `strixhalo` gfx1151; the Linux RX 9000 / R9700 package carries none, because no table matches its hipBLASLt. Only the gfx1151 table is used by default.
- **Two NVIDIA cards, several requests at once: one batch group.** With a layer split over exactly two NVIDIA cards and `--batch N`, the engine now runs one serial group instead of two pipelined groups. Measured on two RTX A4000 16 GB with Qwen3.8-Flash-Next IQ3_XXS, 5 interleaved pairs, aggregate tokens per second: 2 requests +15.9% (5 of 5 pairs), 4 requests +12.0% (5 of 5), 8 requests +14.7% (3 of 3). Every slot's tokens equal the solo run's, and the old default's, under the fixed identity flags (2 and 4 slots, 64 greedy tokens). A single request is not changed. It is not faster everywhere: when most hot experts sit in the CPU, as under the identity gate's small cache, the pipelined groups were about 10% faster (24.4 against 22.0 tok/s), so a card with a very small cache can lose here. `STRATA_BATCH_GROUPS_NV_SERIAL=0` restores the old default; `--batch-groups auto` or a number asks for the pipeline. AMD cards, three or more cards and the single-request paths are unchanged. On the final engine, 4 requests, 5 pairs: 78.06 against 65.97 tok/s (+18.3%, the old default faster in 0 of 5), and every slot's tokens equal the solo run's.
- **A card that draws no display keeps less in reserve.** The reserve of graphics memory the engine leaves free is now 512 MiB (700 MiB with pictures) on a card the probe says drives no screen (a compute-only card), instead of 1536 MiB. A card that drives a display keeps the 1536 / 2048 MiB safety default, and a number you set yourself (0 included) is always used as it is. Only the amount of free memory changes, so the answers are identical and the expert cache gets room for more experts. We did not time this ourselves: the report behind it (#3215) measured 80 against 50 tok/s with the forced reserve. Where the probe cannot tell (AMD and Intel on Linux) the safety default stays.
- **Packed models (`experts.bin`) on Linux: I/O prefetch and the decode gate are on when the page cache has room for at least 55% of the experts.** Measured on an RTX 3060 12 GB (Core Ultra 7 265), Qwen3.8-Flash-Next IQ3_XXS 43 GB pack with `--mmap-experts`, RAM limited to 32 GB by cgroup, cold page cache, 5 interleaved pairs: decode story / code / document 26.0 / 28.3 / 18.5 to 35.2 / 34.4 / 24.7 tok/s (x1.38 / x1.21 / x1.33, 5 of 5 pairs each), a 4K prompt x1.04 (4 of 5), a 20K prompt x1.06 (5 of 5). Same answers: the fixed-flag identity gate (10 prompts, 4K and 20K exact prompt checks) is identical with no RAM limit and with the 32 GB limit. With 16 GB of RAM the page cache holds 38% of the experts, so the default stays off: with it on, a cold 4K prompt read 4 to 6% slower. `STRATA_IO_PREFETCH=0` turns it off and `=1` forces it on. Linux only; only the IQ3_XXS pack was tested (not Q2_0, IQ3_S or Coder packs).
- **AMD RX 9000 / R9700 on Linux: the engine opens its GPU queues in a fixed order at start.** Before, about half of the fresh engines with MTP read prompts 8 to 14% slower, depending on which compute pipe the card's firmware gave the engine's two busiest queues (both on one pipe was slow). The engine now opens two queues on its main thread before anything else starts. Measured on two Radeon AI PRO R9700 boxes (Linux, ROCm 7.10, Q2_0 with MTP): without the fix 10 of 32 fresh starts read the 4K prompt under 2,000 tok/s (about 2,290 for a fast start); with it 0 of 32. Decode against the fix switched off, 20 interleaved rounds: 1.000 / 1.001 / 1.000 (story / code / facts). Opening more queues cost decode (five queues: 2 to 3.6% slower), so two is the default. Same answers: the identity gate (10 prompts, 4K and 20K exact checks) is identical for Q2_0 and IQ3_XXS, also with the 0.2.0 prompt defaults on. `STRATA_HIP_QUEUE_PRIME=0` turns it off. One card was measured; Windows and RX 7000 cards are not changed.
- **Linux hybrid CPUs with low-power E cores (Core Ultra "Meteor Lake" / "Arrow Lake-H", #3262).** The engine and setup now count the cores listed in `cpu_lowpower` as efficiency cores. A Core Ultra 7 255H used to look like 8 P and 8 E cores, so the hybrid plan did not apply and 15 workers ran; it now plans 10. The reporter measured the 15-worker default about 35% slower than 9. We have no such CPU and ran unit tests only (the plan and a fake `/sys`); only the number of workers changes, not the answers.
- **Two GPUs of different architectures (HIP): no start-up warm-up (#3204).** The warm-up product that runs on every card at start made prompts about 25% slower on a split of gfx1151 and gfx1201 for the reporter (`STRATA_PREFILL_WARM=0` restored them). It now runs only when every visible card has the same architecture. We have no mixed pair; on two R9700 (same architecture) the warm-up costs nothing (3,855 against 3,853 tok/s at a 32K prompt, 5 pairs), so the change leaves them as they were. The first request on a mixed pair pays the 1 to 2.5 s library load again, as before 0.2.0. `STRATA_PREFILL_WARM=1` / `0` overrides.
- **Linux, models read in place: a drive probe decides between the file cache and unbuffered reads (#3237).** The room rule picks the file cache when RAM seems to have room, which was 2x slower in prompts and 3 to 4x slower in decode for a reporter with a PCIe 5 drive (about 8 GB/s). When the rule says "cache" and the cache would hold under half of the reads, the engine now reads 96 random 1 MiB pieces both ways at start (under 2 s) and goes unbuffered only if the drive reads at least 4 GB/s and is faster that way. Every drive we have (1.6 to 3.1 GB/s) keeps the file cache; on a 2 GB/s NVMe the cache was better for decode (up to x1.6) and unbuffered reads better for prompts, the opposite of the report. Untested on a fast drive; the answers cannot change (only where reads go), and no identity gate was run. `STRATA_FILE_TIER_PROBE=0` turns it off.

## Fixes from user reports

- **Settings overwritten (#3215, #3270, #3216).** The app forced `--vram-reserve-mib` to 1536 (2048 with pictures) on every Load whatever your file said, which cut decode from 80 to 50 tok/s for one reporter, and a setup run that a Load started dropped every option it did not choose itself, control vectors included. Options set by hand are kept now and win over generated ones; an old file's hand edits are moved into `user_args`.
- **Choosing graphics cards (#3203, #3195, #3256, #3221, #3211).** Automatic no longer picks a card the engine has no code for (an AMD integrated GPU in front of a discrete card). One selected card is sent as a single card, not as a list the installer refuses. A card order from the settings file (`"gpu": [1,0]`, `"gpu_order": "as_given"`) is kept instead of being replaced by the app's own pick. The card list no longer ticks two cards with one click when two makes both count from 0. The dropdown rows fit long card names. The Monitor opens on the cards the model is assigned to.
- **Downloads (#3257, #3214, #3193).** The draft-layer download shows its progress in the app (it showed "0.0 / 0.0 GB"), runs again on a flaky link with fewer connections, and has one writer per folder. Cancelling, or a killed setup, now ends the whole process tree on Windows, so no orphan keeps writing. Gyro's low-RAM pack is written with `--compat-bf16`, which stopped the "command failed (exit 1): python.exe" at the packing step.
- **Re-download of a model you already have (#3199).** A model loaded from your own GGUF folder keeps that folder, so unloading and loading it again no longer downloads it a second time.
- **FP4-Local setup died at step 6 (#3227).** Setup now installs the pinned torch, transformers and safetensors the converter imports, before a prepare that needs them, and names a missing package at once instead of after 20 minutes.
- **The model stopped while starting (#3192).** A start that stopped because no graphics memory was left for the expert cache is tried once more with less kept free.
- **Crash on launch (Windows 11, exit code 0xC0000409, no log).** A failed start on Windows and Mac now leaves a log and a crash file in the app folder and shows a message box instead of closing. The reporter's own panic message is still unknown, so please send the new crash file if it happens again.
- **MTP, context and pictures setting kept coming back.** Every Load re-ran setup and rewrote them. A Load of an installed model is now direct, the picture-off choice sticks, a custom context size is shown and accepted, "MTP per request" is no longer frozen, and the new Draft layer switch is in Expert settings.
- **Your model library no longer moves.** `strata launch --data-dir` with a new folder used to move all existing models, packs and MTP files into it and rewrite your settings. It never moves them without asking now.
- **Math in the chat (#3268).** Formulas are drawn with KaTeX: `$...$` and `\(...\)` inline, `$$...$$` and `\[...\]` as blocks. KaTeX and its fonts ship with the app, load only when an answer has a formula, and work offline. Prices like "$5 and $10" and anything in code stay text. Checked with the formulas from the report in a browser.
- **Windows with a non-UTF-8 code page, such as Russian (#3202).** PowerShell output (the Documents folder, the save dialog, fonts, GPU names) was read in the wrong code page and came back as question marks; it is read as UTF-8 now. Python runs in UTF-8 mode from the launchers and the app's child processes. The engine and the picture reader carry a UTF-8 manifest, so a Cyrillic model folder arrives intact (Windows 10 1903 or newer). We reproduced the first two and tested the manifest with a small program; we could not run the engine on a Russian Windows, so a retest is welcome.
- **Install folder (#3186, #3190).** The Windows installer asks for the folder (another drive when C: is short). Updates and silent installs keep the earlier folder. The docs say what stays on C: (the engine bundle, settings and chats) and that `STRATA_COMPONENTS_DIR` moves the engine bundle. We compiled the page logic with NSIS on a reduced script; the full installer is built at release.
- **Linux engine killed with signal 9 and no out-of-memory (#3238).** A desktop with PipeWire and no rtkit can leave a finite `RLIMIT_RTTIME`. The server now warns at start when the limit is finite, and the engine-died message names it before the RAM hint. There is a troubleshooting entry.
- **Tools find `gguf-py` in the Control package (#3269).** `tools/iq_pack.py` also looks in the install folder (`STRATA_INSTALL_DIR`, the app folder); the error names `STRATA_GGUF_PY`.
- **Intel SYCL build (#3219).** `sycl/tools/build.sh` stops before the long compile when the `ocloc` of the base image is the one that crashes on the int8 kernels (Compute Runtime 26.22.38646.x, IGC 2.36.3) and says to `docker build --pull`; `STRATA_SYCL_I8_ESIMD=OFF` builds without those kernels (slower prompt experts, same answers). We could not reproduce the crash itself: a newer `ocloc` (26.31) builds the Battlemage target without errors.
- **gfx906 (MI50, Radeon Pro VII) builds again (#3172, #3271).** The Qwen3.6 engine is not built for it, the W4A4 target gets `GGML_USE_HIP`, and the trellis overlay and `moe_f16_kq` sources are in the HIP list. All 161 targets compile for gfx906 and `strata` links; we have no gfx906 card, so it was not run on one.
- **Trellis overlay with newer llama.cpp (#3217).** The overlay follows the signatures of the ggml-cuda it patches. On the pinned commit the generated files are byte-identical to before; against upstream 0ce8cd11 the old overlay failed to compile and the new one does.
- **Settings text (#3208).** "Allow browser origins" says it does nothing in the app (the app's API already allows pages of any site) and where `cors_origins` goes, in all eight languages.
- **Docs.** Build from git on Linux (#3191), the dual-socket CPU pool measurements, IOMMU check and no-numactl note (#3201; the NUMA-split pool from that report is not merged), and a two-card gfx906 tip with `--pipeline-windows 2` (+36% decode) and `--trim-stage-weights` (+5% prompt), measured by the reporter and off by default (#3173).

## Privacy

- Update checks run only when you click. Opening Settings, Engine and Update makes no network call; the last result is shown from your computer, and a new check starts only from the button. Offline, the check says "No internet connection. Strata works without it; try again when you are online."
- The assistant asks before it first searches the web or opens a web page. In Manual mode you are asked once per chat and the answer holds for that chat. Settings > Tools has a switch to skip the question (off by default), and a scheduled task cannot search unless you turned that on. Bypass mode does not ask.
- Starting, loading and chatting with a model on disk make no network calls. A test starts the host with every non-loopback request recorded and finds none. The old starter-model list can no longer download anything; it is display only.
- What Strata downloads and when is in `docs/SAFETY.md`.

## Known limits

- **Windows:** the installers are not code-signed yet, so Windows shows "Windows protected your PC": choose **More info**, then **Run anyway**.
- **Windows with an AMD card:** nothing has run on a real AMD card on Windows. The gfx12 prompt defaults and the 780M prompt set are off there. The Windows `rdna3` package (RX 7000 and Strix Halo) was built and scanned but not run on those cards by the maintainers.
- **Radeon 780M:** the GPU can reset with a firmware error (MES REMOVE_QUEUE) when the kernel moves memory the GPU uses. On our box the default engine lost 1 to 4 of 10 starts to it with or without the new prompt set, and the driver recovered each time. The firmware is the cause; we did not install new firmware.
- **Intel Arc Battlemage (B-series):** pictures stay opt-in. A first picture on a B70 once reset the card (xe driver); we could not repeat it on the A-series card and no B-series card was available for 0.2.1.
- **Mac:** the GPU picture reader was measured on an M4 only. The CPU reader is about 50 seconds per picture.
- **Strix Halo:** the hipBLASLt table default rests on a community measurement; please send the start-up line `hipBLASLt tuning table: ...` and a prompt run with the table on and off.
- **Docker:** the `rocm-gfx110x` and `rocm-gfx1151` images were not run on a card, and there is no Intel image.
- **AMD and Intel on Linux:** the engine cannot tell whether a card drives a display, so the safety reserve (1536 MiB) stays unless you set one.
- **Benchmark:** `strata bench run` implements the draft protocol; a first real run on a release engine is still to come.
- **Two NVIDIA cards, batch:** a card with a very small expert cache can be slower with one group than with two (see New defaults).
- **A100 (sm_80), #3252:** a report of decode -10% and prompts -20% since 0.1.45 was not reproduced. On a Tesla P100 (sm_60) and two RTX A4000 (sm_86) the 0.1.45 build against 0.1.44.1 measured decode x1.015 and x0.992, prompts x1.004 and x1.022 (5 interleaved rounds each), and the 0.2.1 tip is 7 to 10% faster in decode than 0.1.45 on both. Reading the commits found no sm_80-specific change. We have no A100; the reporter's numbers are needed.
- **Fast drives, #3237:** the drive probe above is proposed and untested on a drive over 4 GB/s.
- **NUMA-split CPU pool (#3201):** not part of 0.2.1; we have no dual-socket box to measure it.

Two installers and two engines were added to this release later: `Strata-0.2.0-beta-windows-hip-rdna3.exe` (Windows, RX 7000 series and Ryzen AI Max; GPU code for gfx1100, gfx1101, gfx1102 and gfx1151; ROCm 10.2.0a20260930) and `Strata-0.2.0-beta-linux-amd-strixhalo.AppImage` (Linux, Ryzen AI Max; gfx1151; ROCm 7.14.1). The signed update feed is now sequence 101 and lists the two engine packages; `latest.json` and every other file are unchanged. Any other app installer works too: install it, then press **Update engine** in Settings (or run `strata update` in the Terminal) and the matching engine downloads.

## What is new

**Three parts that share one engine.**

- **The Strata app** for Windows (installer), Linux (AppImage) and Mac (Apple silicon, macOS 15 or newer, `.dmg`). Chat with a coding agent that asks before it acts (Manual) or works freely (Bypass), web search, `/loop`, pictures pasted or dropped into the chat, a Models page, a Storage page, a choice of which graphics cards a model uses, two models on two GPUs, sharing with other devices (needs an API key first) and setup of your coding apps.
- **The Terminal**, one line to install (`curl -fsSL https://github.com/Niko1221/Strata/releases/latest/download/install.sh | sh`, `irm https://github.com/Niko1221/Strata/releases/latest/download/install.ps1 | iex` on Windows). `strata launch` is the guided flow (choose a model, tune it, serve it, watch it) and also runs without screens from flags; `strata connect` writes and checks the setup of OpenCode, Codex CLI, Claude Code, oh-my-pi, pi, Hermes Agent and OpenClaw; `strata models`, `strata update`, `strata doctor` and `strata bench run` are there too. The monitor `strata launch` opens has seven views, `1`-`7`, the seventh is Connect. See `docs/TERMINAL_LAUNCH.md`.
- **The engine**, the part that talks to your card, is a separate package per platform and card. The installers carry one, so a new install starts a model without a download. Later engines come from a feed that is signed (Ed25519) and checked file by file, test-started before the switch and rolled back on any failure; models and saved tunings are never replaced. Update with `strata update` or Settings > Update. See `packaging/UPDATES.md` and `SECURITY.md`.
- **A missing engine is a warning.** `strata launch` and the app say in plain words what is missing and what to do next, and still download the model.
- Starting a model and serving never download anything; downloads are one explicit step.

**Pictures are on by default on NVIDIA and AMD cards.** The picture reader runs on the CPU for a card under 24 GB (a few seconds per picture, nothing taken from the card) and on the graphics card from 24 GB. NVIDIA, AMD and Intel follow the same rule; `--vision gpu` / `--vision cpu` / off still choose per model. AMD now has a GPU reader with an automatic CPU fallback (the server prints one line when the GPU reader cannot start). Measured on a Radeon AI PRO R9700: a 260-token picture 57 ms on the GPU reader against 3.13 s on the CPU, a 972-token picture 0.40 s against 14.1 s; the GPU reader keeps 1,470 MiB of VRAM. On a Radeon 780M 0.40 s against 2.42 s. Gyro and the NVFP4 models read pictures too (Gyro needs engine 0.1.45.1 or newer). The Mac app has no picture reader yet.

**Models.** Qwen3.6-35B-A3B has its three sizes in the app's catalog; the NVFP4 models have clear names. The app and
`strata launch` now suggest a model by RAM and graphics memory together: 40 GB, Swift 1.5 IQ2_XS (or Gyro-M, slower);
48 GB, IQ3_XXS; 64 GB or more, IQ3_S (the original or Swift 1.5). With less memory, low-RAM mode starts by itself and the
model runs slower.

**Downloads are faster and checked.** Big files come over 8 connections at once (on the test PC 40 MB/s with one
connection, 77 MB/s with eight) and continue where they stopped. Every model file has a fixed SHA-256 and size, and a
download stops if the pinned version is gone from Hugging Face. Once a model is downloaded, Strata runs without internet.
What Strata downloads and when is in `docs/SAFETY.md`.

**The app's chat.** A finished page, document or picture opens in the sidebar by itself (the Open button opens it in your
browser or default app). A chat without a chosen folder uses `Documents/Strata/Workspace`, so its files open and show in
their folder. The first message no longer fails while the assistant's tools start, and sending with no model loaded says so.

## New defaults, with what we measured

Every speed number below is a median of interleaved pairs against the previous default on the same box (a fresh engine per run); "pairs faster" counts the pairs the new default won. Each default has an off switch.

- **NVIDIA RTX 30 / A-series (sm_86) and Pascal (sm_60): decode.** A per-architecture table of nine (sm_86) and seven (sm_60) switches, picked by removing one at a time and keeping only those that cost speed when removed. RTX 3060 12 GB 60.36 to 66.52 tok/s (+10.2%, 8 of 8 pairs), RTX A4000 16 GB 51.16 to 57.82 (+13.0%, 8 of 8), Tesla P100 16 GB 36.56 to 41.76 (+14.2%, 8 of 8). Same answers: the fixed-flag identity gate (10 prompts, 4K and 20K exact prompt checks) is identical on all three. `STRATA_SM86_PERF=0` / `STRATA_SM60_PERF=0` turn the table off. We left a prompt chunk above 8192 off on NVIDIA (not bit-exact on CUDA) and `STRATA_ROUTE_PRIOR=0.5` opt-in (KL 0.0126 against a run-to-run floor of 0.0012).
- **AMD RX 9000 / R9700 (gfx12), Linux: prompt reading.** The WMMA prompt attention and the fused Q2_0 prompt experts are on. On an R9700 32 GB, Q2_0: a 4K prompt 1,151 to 2,286 tok/s and a 20K prompt 1,384 to 2,751 (1.99x, 5 of 5 pairs). IQ3_XXS: 4K 1,369 to 1,436 (1.05x), 20K 1,576 to 1,997 (1.27x). Decode is untouched (0.999 like for like, same tokens). The text changes slightly: teacher-forced KL 0.0003 (28 prompts) and 0.0015 (long documents), task suites equal; with both on: HumanEval 155/164, reasoning 27/30, agent 6/6, needles 6/6, tool calls 5/5. `STRATA_HIP_WMMA=0` and `STRATA_PF_FUSED=0` turn them off. On Windows they stay opt-in until tested there.
- **Intel Arc A-series (Alchemist): prompt reading.** The XMX path (`STRATA_PF_XMX=2`) is the default. On an A750, 4K prompt 79.5 to 113.0 tok/s; by length (previous default / new) 1K 35.1 / 46.4, 2K 61.7 / 83.1, 6K 66.3 / 114.8. The logits equal those of the old opt-in; `STRATA_PF_XMX=0` brings back the previous default bit for bit. Not for Battlemage (it loses 7-11% there).
- **Intel Arc A750: a prompt deadlock is fixed.** A prompt of about 5,000 tokens could hang the engine in the driver on pageable memory (the engine stopped, HTTP 503); the reproduction hung 6 of 6 before, completes 3 of 3 now, with identical first-token logits and needles 9 of 9 twice.
- **Intel Arc B-series (Battlemage, B70): int8 experts for prompt reading.** On by default: 1K prompt 648 to 785 tok/s (+21%), 4K 1,264 to 1,419 (+12%), same output; `STRATA_PREFILL_MMQ=0` turns it off. Setup now picks an 8192 prompt chunk for a Battlemage card of 24 GB or more with a context over 32K: 16K prompt 1,222 to about 1,350 tok/s (+10-11%), 32K 1,187 to about 1,370 (+15-16%), decode unchanged.
- **Linux, models read in place from the GGUF: RAM and SSD.** Zero-copy page-cached experts, I/O prefetch with a gate that checks it pays, and a RAM check that counts the container's clean page cache. On a 12 GB card emulated on a 72 GB card with the RAM limited by cgroup (Q2_0, three pairs): with 32 GB decode 1.70x / 2.56x / 2.88x, prompts 1.54x / 1.91x; with 16 GB decode 1.16x / 1.25x / 1.25x, prompts 1.63x / 1.68x; with an 18 GiB RAM tier decode 1.16x / 1.10x / 1.30x. On a real RTX 3060 the zero-copy part alone gave decode 1.14x / 1.44x / 1.47x. The gates are identical (Q2_0 and IQ3_S, with and without `--mmap-experts`). Packs in `experts.bin` keep the old behaviour. Off: `STRATA_COLD_OVERLAP=0`, `STRATA_IO_PREFETCH=0`, `STRATA_IO_PF_GATE=0`.
- **The prompt chunk now accounts for RAM and SSD (file tier, Linux).** Where today's chunk would make the file set bigger than the page cache, the engine picks a smaller one. Measured on an RTX 3060 with the SATA SSD emulated (cgroup RAM limit and a 450 MB/s read limit, five pairs): a 20K prompt 334 to 822 tok/s (2.46x), a 29K prompt 419 to 910 (2.17x), drive reads for the 29K prompt 29.5 GB to 0.6 GB, decode after the prompt 28.6 to 45.7; a 4K prompt unchanged. Where the file set already fits the page cache (the 5070 test PC) it changes nothing. Tested on CUDA only. `STRATA_PREFILL_HOST_PLAN=0` turns it off.
- **CPU worker counts follow the physical cores** (host socket, container quota, cap 32), and setup no longer writes half the logical threads (it wrote 128 on a 256-thread machine). Too many workers cost real speed: with as many workers as logical threads decode fell to 0.65-0.73 of the default on a 6-core and a 32-core box. Speed at the new defaults equals the old within noise (R9700, 31 to 30 workers: prompt 1.005-1.007, decode 1.000-1.007). A configured count above the plan still runs, with a warning.

## Fixes from the owner's tester reports

- **Gyro-S gave empty or garbage answers on RTX 50 / RTX PRO (Blackwell).** The fused gate/up kernel assumed 80 dots per row and computed half of each row for Gyro's trellis types. Fixed; four test prompts failed before and pass now. Laurent Zuijdwijk's Gyro fork carries the same fix.
- **Windows: a clean PC could not start the engine** (it needed `cublas64_13.dll` and `cublasLt64_13.dll`, which only a PC with the CUDA toolkit on its PATH had). Packages now carry every library they import, and a package that would miss one is refused when it is built.
- **Linux and Mac: the agent chat never started** (a pruning rule removed a Harness package it imports on every system).
- **Storage "Check folder" unloaded the models;** only a real change of folder does now.
- **The app showed the engine's version as the app version** in Settings > Update.
- **Qwen3.6 showed no sizes** in the catalog and the first-run page.
- **A folder from an old settings file (`T:\Strata`) was adopted as the install folder.** The app passes its own folder now.
- **Downloads:** one progress bar for the model and its picture reader, choices kept when you switch tabs.
- **Web search** stopped after the third search when DuckDuckGo refused; it falls back to another search source and waits before asking DuckDuckGo again. A turn that loops on failed searches, or runs out of context, now ends cleanly and says why.
- **`/loop`** can be stopped by a count, a time or the answer ("stop after 3 answers").
- **Anthropic base URL:** the app and `strata connect` show the address without `/v1`; a pasted `/v1` is cut back.
- **Files edited:** the chat no longer lists files it did not touch after a turn.
- **Cloudflare tunnel:** `cloudflared` is found on your PATH and in the usual places, and a copy that is already running is not started twice.
- **Terminal:** flags no longer crash the start screen; `strata models` finds models the app installed; no web page opens by itself; `strata connect --check --output json` prints one JSON object and exits 1 when a check failed.

## Known limits

- **Mac:** no picture reader yet; macOS 15 or newer. The app and the Terminal are signed and notarised by Apple.
- **Windows:** the installers are not code-signed yet, so Windows shows "Windows protected your PC": choose **More info**, then **Run anyway**.
- **Windows with an AMD card:** the installer and the GPU picture reader are built, but nothing has run on a real AMD card on Windows. The gfx12 prompt defaults are opt-in there.
- **AMD RX 7000 (gfx1100-1102) and Strix Halo (gfx1151):** the packages are built, linked and scanned (library imports, file hashes, the GPU code inside each binary, `--version` in a clean environment, a clean refusal of the Linux packages on an RX 9000 card, update-feed selection tests). The maintainers have not run them on an RX 7000 or a Strix Halo card. What other people ran: an RX 7900 XTX on Windows 11 ran the earlier ready-made Windows engine (0.1.40, report #1173), and Strix Halo owners ran Linux builds made from source on the ROCm 7.14 line (`bench/results/COMMUNITY.md`). Nobody has run Strix Halo on Windows. The packaged AMD engines do not carry the hipBLASLt tuning tables yet (planned for 0.2.1), so prompt reading is slower than the source-build numbers in [STRIX_HALO.md](STRIX_HALO.md) and [AMD_HIP.md](AMD_HIP.md).
- **Mini PCs with a Radeon 780M / 880M / 890M:** the matrix-core prompt defaults are parked. On the 780M the GPU reset (MES REMOVE_QUEUE) when they were tried; the iGPU keeps its opt-in switches.
- **R9700:** about half of the fresh engines with MTP read prompts 10-23% slower than the others (4K: about 1,350 instead of 1,700 tok/s). Not seen on NVIDIA; the cause is not found.
- **Docker images are not published yet;** build them yourself (`docs/DOCKER.md`).
- **`strata code` is not available** in the Terminal; use `strata connect` for coding apps (the app has its own agent).
- The standard benchmark protocol is a draft (`docs/BENCHMARK_PROTOCOL.md`); `strata bench run` and `BENCH.bat` do not implement it.
