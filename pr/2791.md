## What the report is about — and its limitation

This install cannot keep the 36 GB expert arena in 31.6 GiB of RAM, so unlike the two 64 GiB 5070 Ti reports it runs the low-RAM mode and serves the experts through the OS file cache. The measured boundary:

- **decode** lands at ~85-87 tok/s once the cache is warm, roughly half the 64 GiB figures (102 tok/s)
- **prompt processing** is 270-448 tok/s against 1,992-3,523 tok/s at 64 GiB — **4-8x slower**, because the prompt path re-reads lent experts from the SSD

So on a 32 GiB machine the prompt/TTFT side, not decode, is what decides whether the setup is usable (a 16K prompt is 36 s before the first token). The chat row's 36.8-87.0 range is the low-RAM cache warming across the nine back-to-back requests, not run-to-run noise; the report says so in the Results section.

Also recorded because the guide asks for them: storage, PCIe link, power limit and the background load are filled in, and two things the tool got wrong are corrected — it reports the OS as "Windows 10 (10.0.26100)" (actually Windows 11 Pro 10.0.26200) and its own README template asks for facts it cannot read (CUDA version, commit on a zip install).

## One tool bug found while preparing this

`tools/strata_bench.py:564` reads `CMakeLists.txt` with `read_text()` and no encoding, so on a Chinese/Japanese Windows (GBK code page) it raises `UnicodeDecodeError: 'gbk' codec can't decode byte 0xbf in position 2` on the file's UTF-8 BOM and exits **before any measurement**. `setup.py:4649` reads the same file with `encoding="utf-8"`. `PYTHONUTF8=1` works around it. Happy to file it as an issue with the traceback if that is more useful than fixing it in this PR — I left it out of this PR to keep it results-only.
